# Security boundaries

All crawler HTTP goes through `SafeHTTP`; source seeds and every redirect are validated against explicit source-specific host allowlists. HTTPS is mandatory by default, ports are restricted, redirects are bounded and loop checked, timeouts are capped, and response bodies have a hard size ceiling. Private/reserved hosts — loopback, link-local, RFC1918, documentation ranges, IPv6 unique-local, and `localhost` — are refused by default to prevent SSRF-style host traversal; the only exception is an explicit operator opt-in meant for controlled local fixture servers. Local HTTP/nonstandard ports are available only through explicit test injection. Candidate APK URLs use that same transport and the source's own host policy.

A trusted 64-hex SHA-256 certificate fingerprint is required in source configuration; candidate/listing signing metadata is untrusted. APK checks cap compressed and expanded archive sizes/count, verify manifest presence, ask `aapt` for package identity, compute SHA-256, and ask `apksigner` to verify the APK and certificate pin. Missing tools, missing fingerprints, malformed artifacts, package mismatch, and signature mismatch cannot be accepted. Quarantine records survive `forget` and source re-registration. Quarantine review is audit-only by default. Only an explicit `--resolve` with a mandatory reason and operator identity resolves the selected record; the item still must pass download, package, and signer checks again. Configuration changes alone never resolve quarantine.

Limitations: no malware engine/sandbox, no reproducible extension build, no SBOM, no signed repository metadata, no DNS pinning, no multi-user review authorization, and no independent audit. A clean verdict means structural/package/signature checks passed; it does not mean malware-free.
